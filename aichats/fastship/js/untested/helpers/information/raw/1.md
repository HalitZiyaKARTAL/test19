> **What this is:** a verified, working writeup of how the mobile game *Kingshot*
> (Century Games) gift-code redemption system works, how to redeem codes via its
> own backend API, how to auto-find live codes, and how to keep the tool alive
> when Century rotates their signing key.
>
> **Use it to:** (1) share openly with the community, (2) brief a future AI agent
> in one message — just link the hosted script and say *"check this doc + repo"*.

## 2. The official system (architecture)

| Piece | Detail |
|---|---|
| Redeem website | `https://ks-giftcode.centurygame.com` — Vue.js SPA, **obfuscated** (obfuscator.io style hex string tables) |
| Backend API | `https://kingshot-giftcode.centurygame.com/api` |
| Redeem endpoint | `POST /gift_code` (form-urlencoded) |
| Config endpoint | `POST /gift_code_config` (needs signature; returns UI/banner config — **not** a code list) |
| Lookup endpoint | `POST /player` — **now returns 404 server-side** (dead/removed). Don't waste time on it. |
| Captcha endpoint | `/captcha` — 404/not exposed; irrelevant anyway (not enforced) |
| Server | PHP 7.4 / Symfony-style (nginx) behind a WAF/CDN that enforces HTTP methods at the edge |

### Request signing (every request)
Client signs params with:
```
secret = <hidden in JS bundle>
sign = MD5( sortedQueryString + secret )     // hex lowercase
sortedQueryString = k1=v1&k2=v2...           // keys sorted; values encodeURIComponent
```
Body example:
```
fid=<PlayerID>&kid=<Kingdom#>&cdk=<CODE>&captcha_code=AUTO&time=<unixSeconds>&sign=<md5>
```
- `captcha_code` is accepted but **not validated** (`AUTO` or `ZZZZ` works).
- `kid` (kingdom number, e.g. `61`, `1`) **IS validated against `fid`** — mismatch → `USER INFO ERROR (40020)`.

### Server verdicts (ground truth for everything)
| err_code | msg | Meaning |
|---|---|---|
| 20000 | SUCCESS | ✅ redeemed → rewards to in-game mail |
| 40005 | USED | code's global claim limit exhausted |
| 40007 | TIME ERROR | exists but expired / not yet active |
| 40008 | RECEIVED | already claimed on this account |
| 40011 | SAME TYPE EXCHANGE | account already used a code of this *type* |
| 40014 | CDK NOT FOUND | invalid code |
| 40019 | TOO FREQUENT | rate-limited |
| 40020 | USER INFO ERROR | fid/kid mismatch |
| 0 | Sign Error | **bad/old signing key** → triggers auto re-extract |

These verdicts let you **classify codes safely**: probing an unknown code never wastes anything —
`CDK NOT FOUND` = fake, `TIME ERROR` = expired, `SUCCESS` = live (and redeemed),
`SAME TYPE`/`RECEIVED`/`USED` = live but already handled.

### Rate limiting (important!)
- Server returns `TOO FREQUENT (40019)` after roughly **10–12 requests/minute** from one IP.
- **Pace ≥4s** between calls; on `40019` wait **60s** then retry once.
- Response headers show `x-ratelimit-limit: 30` on fresh IPs (per-window cap).
- Don't brute-force guess codes aggressively — you'll get throttled and look bot-like.

## 3. Kingdom auto-lookup (the tricky part, solved)

The official `/player` endpoint is **gone (404)** and was CORS-locked anyway. Working path found:

1. Fan site `kingshot.net` runs a **Next.js Server Action** that looks up a player by ID
   (their server calls Century's backend, so no CORS problem).
   - Action id: `40a98b52a0796b9ad015ccc308355704ea2b8155c4`
   - URL: `https://kingshot.net/gift-codes/redeem`
   - Headers: `Next-Action: <id>`, `Content-Type: text/plain;charset=UTF-8`, `Origin: https://kingshot.net`
   - Body: `["<playerId>"]`
   - Response: React Flight lines; the one containing `"status"` + `"data"` is JSON with
     `{playerId, name, kingdom, level, levelRendered:"TG8", ...}`.
2. That action is **cross-origin blocked & CSRF-checked** — but a public relay can carry it.
   Use **get2post** (below) with the `Origin` header spoofed to `https://kingshot.net`.
3. Only the **kingdom number** is needed for redemption; `name`/`level` are discarded.

## 4. Networking toolbox (what actually worked)

### get2post (`https://get2post.vercel.app`) — the star
A public GET→POST converter (by Tyler Tracy, Sept 2026) that also works as a **general CORS proxy**:
```
POST relay:  /api/post?url=<target>&data=<rawBody>&headers=<json>&response=json
GET proxy:   /api/post?url=<target>&method=GET&response=json     // method=GET is REQUIRED (default is POST!)
```
- Forwards custom headers + body correctly (echo-verified).
- CORS enabled, JSON envelope `{status, headers, body}`; returns upstream `status` inside.
- **Caveats:** logs requests (redacts Authorization/Cookie/sign/keys); blocks nothing public;
  upstream response cap ~1 MiB; **Century's static site returns 403 to it** (Vercel IP blocked) —
  so use it for GitHub/kingshot.net/Century API, NOT for `ks-giftcode.centurygame.com` page/JS.

### GET CORS proxies that worked
- `https://allorigins.hexlet.app/raw?url=` ✅ (reliable for Century static + kingshot.net)
- `https://cors-tube.vercel.app/?url=` ✅
- Many others (`corsproxy.io`, `cors.eu.org`, `codetabs`, `cors.lol`, ...) **hung or failed** — don't waste retries.
- `r.jina.ai` works as a GET text-reader fallback.

### Things that did NOT work (don't retry)
- `X-HTTP-Method-Override: POST` / `_method=POST` GET-override → **405 at the WAF** (method enforced before Symfony).
- Direct cross-origin read of `/player` → blocked (dead route + no CORS on error page).
- `kingshot.net` Server Action called directly cross-origin → blocked (CSRF).

## 5. Key extraction / self-healing (if Century rotates the secret)

The signing secret ships inside the website's JS. Re-extract live:
1. GET `https://ks-giftcode.centurygame.com/` → find `/js/app.<HASH>.js`.
2. GET `app.<HASH>.js` → find lazy chunk name (regex `([A-Za-z0-9_]+_vue)`) → chunk URL
   `https://ks-giftcode.centurygame.com/js/<chunk>.<HASH>.js`.
3. In the chunk, locate the MD5-suffix index:
   `\[['"]MD5['"]\]\)\([^)]*\+[A-Za-z_$][\w$]*\((0x[0-9a-f]+)\)` → e.g. `0x1b4`.
4. Decoder function name = 2nd identifier on first line (`^var\s+\w+\s*=\s*(\w+)\s*;`).
5. `(0,eval)(chunk)` then `decoder(parseInt(hex,16))` → the secret (was `mN4!pQs6JrYwV9`).

`redeemer2.js` does this automatically whenever the server replies `Sign Error`.

## 6. The hosted script (`redeemer2.js`) — API summary

Config: only **Player IDs** (no names in code). Ledger keyed by ID.
```
KSR.redeem(codes[, onlyIds[, skipDone=true]])   // redeem on all/some IDs
KSR.findAndRedeem([seeds])                      // find live codes THEN redeem all
KSR.findCodes([seeds])                          // find only (community list + date patterns)
KSR.probeCode(code[, fid])                      // test one code on one account
KSR.liveFromNet()                               // current codes from kingshot.net JSON-LD
KSR.ledger.summary() / .clear()                 // saved results per Player ID
KSR.kidFor(fid)                                 // resolve kingdom
```
Behavior: kingdom auto-lookup → 4s pacing → 60s backoff on `TOO FREQUENT` →
auto key re-extract on `Sign Error` → results saved → skips already-done.

### Loading rules for agents (important JS gotcha)
- Classic `<script src>` → everything becomes global; call `redeem()` directly.
- `fetch().then(eval)` → top-level `const/let` do **NOT** leak, so use the **`KSR.*` handle**
  (the file attaches `globalThis.KSR`).
- Must run in a browser-like env with `fetch`, `localStorage`, `prompt`. Workers lack
  `localStorage`/`prompt` (script degrades gracefully to the built-in kingdom map).

## 7. Gift-code ecosystem notes

- Community tracker `https://kingshot.net/gift-codes` exposes current codes as JSON-LD
  (`ItemList` → `itemListElement[].name`) — good "what's live now" source.
- Naming patterns: weekly `KS+MMDD` (e.g. `KS0907`), store `OFFICIALSTORE+MMDD`
  (e.g. `OFFICIALSTORE0904`), permanent `VIP777` / `Kingshot888`, event codes
  (`CHILLWEEKEND`, `HAPPYCATDAY`, `FB2500KT`, `VIP0822`, ...).
- Codes expire fast (many die within days); many trackers' "active" lists are stale —
  **trust the server verdicts**, not the blogs.
- New codes usually drop **Fridays/weekends** → run `KSR.findAndRedeem()` then.

## 8. Mistakes & lessons (so you don't repeat them)

1. **Don't trust blog "active code" lists** — verify against `POST /gift_code` verdicts.
2. `/player` (role lookup) is **dead** — use the kingshot.net server-action route instead.
3. get2post defaults to **POST** — always pass `&method=GET` for GET proxying.
4. **CORS ≠ blocked endpoint**: Century JSON responses include `access-control-allow-origin: *`;
   earlier `/player` "blocked" was a 404 error page without CORS headers.
5. Public CORS proxies are flaky — implement **timeouts + fallback chains**, never single-proxy.
6. Obfuscated bundles: eval them in an **isolated context** (worker) to read their string
   tables; top-level `function`s leak but `const`s don't — expose an explicit global handle.
7. Use **MD5 test vectors** (`md5('abc') === '900150983cd24fb0d6963f7d28e17f72'`) to catch
   signer bugs before touching real endpoints.
8. Server pacing: ≥4s between calls; 60s backoff; respect it — getting IP-throttled breaks everything.

## 9. Ethics & safety

- Use only on **your own accounts**; it performs exactly what the official site does.
- The captcha exists to slow bots — the API ignoring it doesn't make automation "approved";
  be polite, low-rate, and don't build spam tools with this knowledge.
- `get2post` and `kingshot.net` log requests — don't send secrets; Player IDs are public-ish.
- Don't publish other people's Player IDs. The hosted script contains the owner's own IDs only.

1. Fetch the raw `redeemer2.js` (link in §1), `eval` it.
2. Use `KSR.*` (not bare globals) — see §6.
